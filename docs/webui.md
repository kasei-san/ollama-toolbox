# web の画面の設計

使い方（画面の見方・操作）は README。ここは**なぜそうしたか**と**既知の粗さ**。

## なぜ自前で持っているか

**公式の Ollama アプリでは足りない。** インストール済みの 0.32.7 が持つ
`%LOCALAPPDATA%\Ollama\db.sqlite` のスキーマを直接見て確かめた（2026-08-11）。

```
TABLES: settings, chats, messages, tool_calls, attachments, users
```

| 要求 | 公式アプリ | 根拠 |
|---|---|---|
| 過去の会話ログが見れる | **○** | `chats` / `messages` / `tool_calls` がある |
| システムプロンプトを制御できる | **×** | **スキーマのどこにも system prompt の列が無い。** Modelfile に焼く以外の手が無い |
| このリポジトリの検索が使える | **×** | MCP / 外部ツール登録のテーブルが無い。`settings` にあるのは `tools` `agent` `browser` `websearch_enabled` の boolean だけで、内蔵ツールの on/off でしかない |

`websearch_enabled` は **ollama.com の web search API**。
これは検索クエリが外に出るという理由で採用しなかったもの
（→ [`search-backends.md`](search-backends.md)）。

公式アプリに乗ると `strip_stale_year` / `SearchFailed` での打ち切り /
上限到達時の回答強制 / 強制検索が**全部使えなくなる**。
つまり [`model-date-sense.md`](model-date-sense.md) に書いた対策が丸ごと消える。

**ollama + MCP で出てくるものは全部サードパーティ**（`ollmcp`、`ollama-mcp-bridge` 等）で、
公式アプリに差す仕組みではない。

## 決めごと

* **127.0.0.1 にしか bind しない。** `web_fetch` がモデルの求めに応じて
  任意の URL を取りに行くので、外から叩ける場所に置くと踏み台になる。認証も無い
* **生成は同時1本。** モデルが1つしか動かないので、2本目は `409` を返して**待たせない**。
  待たせると、待っている側のブラウザが黙って固まる
* **ブラウザを閉じても生成は止めない。** 途中経過を送れなくなっても、
  答えは最後まで作って sqlite に入れる。走らせた推論と検索を捨てるのは惜しい
* **`system` は `None` と `""` を区別する。** `None` は Modelfile の SYSTEM が効く、
  `""` は空の SYSTEM で上書き。**意味が違う**

## 進捗の出し先を切り出してある

途中経過は `emit(kind, payload)` に流す。CLI は stderr、web は SSE。
**エージェント側は誰に向かって喋っているのかを知らずに済む。**

```
think    思考の断片        content  答えの断片
tool     ツール呼び出し     result   ツールの結果
note     こちらからの注記   endturn  ターンの終わり（表示を閉じるため）
```

## 動いていることを見せる

**冷えたモデルの最初の1問は、最初のトークンが出るまで50秒ほど何も起きない。**
そこが一番「固まったのか考えているのか」分からないので、
**ログの最下段**に段階と経過秒を出す。入力欄ではなくログに置いたのは、
会話の流れの中で見えるようにするため。

経過秒も出すのは、「何をしているか」だけだと進んでいるのか止まったのか分からないから。

出力中のブロックには末尾に点滅を出す（**文字が途切れたのか、まだ続きが来るのか**の区別）。
点滅するのは1箇所だけ。`prefers-reduced-motion` が有効なら動きは止まる。

## VRAM インジケーターを2本重ねている理由

1本だと**「空きが無い」のか「このモデルが食っている」のか**が分からない。
下が GPU 全体（`nvidia-smi`）、上が今のモデル（`/api/ps` の `size_vram`）。

`nvidia-smi` は毎回プロセスが起きるので、サーバ側で2秒キャッシュする
（タブが複数あればその数だけ聞きに来る）。タブが裏にいる間は測らない。
ただしそれだけだと表に戻った瞬間の表示が古いままなので、
`visibilitychange` で測り直す。

> **`nvidia-smi` の使用量だけでは溢れを判定できない。**
> アロケータが使える分を使い切るので天井付近に張り付く。
> 詳しくは [`vram.md`](vram.md)。

## エラー表示で踏んだこと

**「検索に失敗した」を一律に被せていた**ので、VRAM 不足まで検索のせいに見えた。
`SearchFailed`（検索の失敗）と `OllamaFailed`（Ollama が受け付けない）を分け、
**画面側では decorate しない**（何に失敗したかはサーバが書く）。

あわせて `str(HTTPError)` が `HTTP Error 500` までしか言わない件も直した
（理由は本文にある）。→ [`vram.md`](vram.md) の「OOM のときに出るメッセージ」

## 既知の粗さ

* **モデルの切り替えがプロセス全体に効く**（`agent.MODEL` がグローバル）。
  生成は同時1本なので競合はしないが、**他の会話の既定も変わる**
* `thinking` はターンごとに1つにまとめて最後の assistant に付けている。
  ラウンドごとには分けていない
* **認証が無い。** 127.0.0.1 に閉じていることだけが防御
