# 会話の文脈の持ち方

使い方（どこで文脈が続くか）は README。ここは**どう実装したか**と**なぜそうしたか**。

## Ollama は覚えてくれない

`/api/chat` は**ステートレス**で、履歴はクライアントが毎回まとめて送り直す仕様。
**覚えているかどうかはこちら側の実装次第**であって、Ollama の機能ではない。

最初の実装は `ask()` が呼ばれるたびに `messages` を作り直していたので、
対話モードでも前のやり取りがどこにも残らなかった
（[issues/8](https://github.com/kasei-san/ollama-toolbox/issues/8)）。

## ターン単位で持つ

`Conversation.turns` は「1ターン = 質問から最終回答まで」のリストのリスト。
ただの `list` にしていないのは、**溢れて古いものを捨てるときに
ツール呼び出しと結果のペアを壊さないため**。

**`role: tool` と、それを呼んだ assistant の `tool_calls` は必ずセットで落とす。**
片方だけ残すと、応答の無い呼び出しや呼ばれていないツール結果が履歴に残り、
モデルが混乱する（テンプレートによっては生成自体が壊れる）。

過去ターンの `thinking` は積まない。Qwen 系のチャットテンプレートは
そもそも過去の思考を渡さない設計なので、積んでも嵩むだけ。

打ち切り時に差し込む `STOP_SEARCHING` も履歴に残さない。
こちらが差し込んだ指示であって、ユーザーの発言ではないため
（残すと次ターン以降ずっと効いてしまう）。

## 溢れたら古い方から捨てる（黙って忘れない）

`num_ctx` を超えると Ollama は**前から黙って切り捨てる**。真っ先に消えるのは
先頭の SYSTEM で、**日付まわりの禁止が効かなくなる**
（→ [`model-date-sense.md`](model-date-sense.md)）。
それを避けるため、履歴が予算を超えたら自分で削る。**削ったら必ず伝える。**

1. **古いターンから検索結果だけ剥がす** — 検索結果は1件で最大 8000 文字積む割に
   後から効きにくい。会話の筋（何を聞いて何と答えたか）の方が残す価値が高い
2. それでも足りなければ**ターンごと**捨てる

予算は `num_ctx` の半分（`HISTORY_CTX_RATIO`）。残りは今のターン用に空けておく。
1件の tool 結果だけで 8000 文字積むので、半分空けておかないと今のターンの途中で溢れる。

## トークン数の見積もりは粗い

**文字数 ÷ 係数**でしかない。日本語と英語で1トークンあたりの文字数が倍以上違うので、
これ単体では当てにならない。

そこで応答の `prompt_eval_count`（**実際に送られたトークン数**）を毎回読んで
係数を補正している。初回だけは見積もりのままなので、そこは粗いまま。

`prompt_eval_count` にはツール定義（毎回送られる。約200トークン）が含まれるが
文字数側には無いので、**係数は本来より小さめに出る＝見積もりは多めに出る**。
早めに削る方向なので、ズレるならこちらで構わない。

## `num_ctx` の取り方

1. 起動時は `/api/show` の `PARAMETER num_ctx`
2. モデルがロードされた後は `/api/ps` の `context_length`（**実際に確保された値**）で上書き

> **`model_info` の `<arch>.context_length` は使ってはいけない。** あれは
> アーキテクチャ上の最大（このモデルなら 262144）で、Ollama が確保する量ではない。
> 効いているのは `PARAMETER num_ctx`（40960）の方。
> 取り違えると「まだ余裕がある」と誤認して溢れる。

`PARAMETER` の無いモデルでは Ollama 側の既定になる。0.32.7 では 4096
（`/api/ps` で確認済み）だが**バージョンで変わりうる**ので、
ロードできたら実測値で上書きする作りにしてある。

## web の画面は sqlite が正

メモリ上の状態を持たず、毎回ログから `Conversation` を組み直す。
だから**サーバを再起動しても、別のタブから書いても同じ文脈**になる。

`thinking` は表示用に保存するだけで**文脈には戻さない**。
検索の失敗は `role='error'` で記録し、こちらも戻さない
——モデルの発言ではないため。

ターンは最後まで通ってから積む。途中で `SearchFailed` が飛べば
**質問ごと履歴に残らない**が、モデルが答えていない以上それが正しい。
